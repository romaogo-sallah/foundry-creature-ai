# Wolf rules coverage audit

Audited 2026-11-03 against module **0.5.2**, the supplied Monster Core wolf export, the current adapter/planner/reaction handlers, and the linked PF2e rules. This is a coverage review, not an implementation change. Existing tests establish the supported subset; they do not establish coverage of all PF2e rules.

**Historical audit:** version **0.6.0** subsequently implemented the first group: Step, Crawl/prone choices, supported Escape sources and outcomes, conservative physical attack-path checks and remaster Knockdown valuation. The [maneuver guide](wolf-maneuvers.md) describes current coverage and remaining limitations. The table below records the 0.5.2 findings.

The live wolf generates **Stride, Stand, Jaws Strike, Knockdown, and End Turn**. Recovering a chooser capable of comparing other options does not generate or execute those options in Foundry.

## Confirmed stat block

The supplied wolf has Jaws +9, Athletics +6, Acrobatics +7, Perception +7, land Speed 35 feet, low-light vision and **imprecise scent 30 feet**. It has Pack Attack and one-action remaster Knockdown. These match the [Monster Core wolf](https://2e.aonprd.com/Monsters.aspx?ID=3241). The anatomy/ability requirements for an action still matter; adding every humanoid skill action would not produce an appropriate wolf policy.

## Rules execution versus tactical evaluation

Native PF2e rolls and damage calls are already used for supported Jaws and remaster Knockdown outcomes. Ordinary MAP on the supported Strikes, Pack Attack's two-other-allies threshold, Knockdown's one-action cost/MAP exception, and native resistance/weakness/immunity damage application have existing coverage. Reimplementing those calculations inside the planner would risk disagreeing with Foundry.

The chooser still uses DD's estimated defenses and simplified hit probability. It does not fully predict critical damage, situational AC modifiers or mitigation when comparing targets. Actual rolls can be correct while the selected target is tactically poor. An improved evaluator should use observed/estimated information, not secretly read every opponent's undiscovered defenses or exact HP.

Likewise, these are policy choices rather than universal PF2e rules:

- How aggressively a wolf risks its life to keep Pack Attack or flanking.
- Retreat after serious injury or loss of pack members, unless a condition explicitly dictates flight.
- Preference for visibly vulnerable prey rather than a fixed focus target.
- Whether to attack unconscious prey. Current target filters exclude it, although unconscious is not a blanket prohibition on attacking a creature.
- Anticipating future pack members' movement, protecting routes for them, or using a prepared attack.

These policies should be configurable by creature or encounter. They should not be presented as mandatory rules or as recovered DD wolf-specific instructions.

## Suggested implementation order

1. Fix/validate target legality: physical line of effect, observer-specific perception and differences between conditions that restrict movement and those that restrict attacking.
2. Add Step and Escape, with source-specific DCs, MAP and result handling.
3. Expand prone decisions and replace automatic remaster Knockdown priority with an estimate of its risk and benefit, while retaining the actual action rules.
4. Add restricted action pools and condition-driven behavior. Reject unsupported minion execution rather than awarding a normal autonomous turn.
5. Add reaction trigger stages around attacks, keeping the existing wait/owner/ordinary-reaction protections.
6. Add environmental movement and recovery handlers, then optional pack coordination and morale.

This audit changes no installed automation behavior. Each subsequent rules handler should have a concrete scenario test and a live encounter check before it is treated as covered.
