# Wolf automation for Foundry PF2e

Version **0.8.0** adds [entertainment preferences and pack morale](wolf-pacing-and-morale.md): ability showcase scores, front-line engagement and coordinated retreat. Both default on. Controls let the GM adjust the showcase bonus and separate packs. Since **0.9.1**, front-line characters are calculated automatically from maximum HP and current AC. Existing movement, reactions and action accounting remain in force.

Version **0.7.2** fixes Escape opening a check dialog when the GM enables PF2e check dialogs. Automated Escape now uses the same preference-aware roll event as jaws and Knockdown, rolling immediately with either preference. Escape source/DC setup and reaction prompts retain their existing purpose.

Version **0.7.1** fixes [Escape from PF2e Automations grapple effects](wolf-escape-automation.md), including locked Restrained/Grabbed children and automatic use of their recorded attacker DC. Reload all clients with **Ctrl+F5**.

Version 0.7.0 adds [follow-up scoring, safer routes and decision explanations](wolf-decision-improvements.md) to the reconstructed Dawnsbury Days 4.44 ranking and Foundry PF2e wolf action handlers. Step, Crawl, Escape, prone choices, physical attack-path checks and remaster Knockdown valuation remain supported. See the [maneuver guide](wolf-maneuvers.md) and [behavioral extraction report](dawnsbury-ai-behavior.md) for setup, provenance and adaptations.

Built against the installed Foundry 14.369 and PF2e 8.6.1 interfaces. Automated tests use Foundry/PF2e test doubles; an actual running-world smoke test has not been performed.

Version 0.2.1 fixes Wolf detection for PF2e's prepared array-form damage selectors. Both compendium string selectors and prepared arrays are accepted, and ability validation reports which component is missing. After installing an update, reload the Foundry client with **Ctrl+F5** to load the updated scripts.

Version 0.2.2 supports global combats that are not linked to a Scene by checking the active Combatant's scene. It also adds a paw button to the token toolbar. **Run turn** and **One action** save the targets and settings in the controls before acting; **Preview** uses those settings without saving them or enabling automation.

Version 0.2.3 permits movement on scenes with empty Regions or only disabled Region behaviors. Blocked choices now explain excluded targets or movement restrictions in the GM report and Preview. Remaining actions can be retried, including actions incorrectly marked finished by earlier versions; the action budget is never increased.

Version 0.2.4 fixes the grid-alignment guard. Movement starts at the token's actual coordinates, uses Foundry's native snapping to identify the nearest square, and submits snapped destinations. Fractional or off-grid origins no longer require manual snapping, and previewing does not reposition the token.

Version 0.2.5 accounts for Foundry's accumulated movement history when granting each Stride its own Speed budget, including diagonal parity. It waits for movement animations before making another decision and reads authoritative token coordinates. Equal-cost routes prefer shorter geometric paths and fewer bends. Once a supported bite is available the wolf attacks; it chooses flanking positions while approaching. The GM report shows each Stride's distance and purpose. A native stopped Stride pauses with a known spent action instead of throwing an uncertain-outcome error.

For a turn already interrupted by an error in an earlier version, use **Correct counts** once and save the existing remaining-action/Strike counts after checking the result. This clears the old uncertain marker without refunding actions. A new turn receives its normal budget.

Version 0.2.6 recognizes the supplied Monster Core wolf's existing Jaws, one-action Knockdown, and passive 1d4 Pack Attack and lists them in the controls. It adds a separate **Advance to next combatant when finished** checkbox, off by default. The active GM requests Foundry's native next turn once after a full run spends its action budget, or all assigned enemies are defeated or unconscious. One action, Preview, manual damage, stopped movement, cancellation, unresolved rolls, and blocked or missing living targets hold the turn. Uncertain advancement requests require the GM to use the combat tracker instead of retrying automatically.

Version 0.2.7 fixes repeated Stand attempts when Prone does not clear. A single Stand deletes all removable Prone entries present at the start, waits for the embedded update, and verifies the current token actor is standing. Locked or temporary condition sources require manual handling before spending an action. If Prone remains after the update, automation stops with the attempted action reserved; it cannot repeatedly spend Stand actions or advance combat. Check the condition sources and use **Correct counts** after resolving the result. A later, separate knockdown can still require another Stand.

Version 0.2.8 adds a final already-prone check before executing Knockdown, for both remaster and legacy wolves. The chooser already excludes prone targets. If the target becomes prone while the action reservation is saved, Knockdown is skipped without a Trip roll or action cost and the remaining turn is reconsidered. Only this confirmed unexecuted action releases its reservation; interrupted rolls keep their existing costs.

Version 0.3.0 replaces the blanket movement-in-reach error with [owner reaction prompts](reactions-foundry.md). Shield Block is offered before automatic physical attack damage; Reactive Strike is offered on threatened departures along a Stride and after Stand resolves. The active owner chooses, or the GM if no owner is online. One ordinary reaction is tracked across both abilities and refreshes on the creature's own turn. Reload **every connected client** after updating so the player prompt handler is available.

Version 0.3.1 adds a shared reaction wait across AI runners. New actions and turn advancement wait until every pending reaction decision, roll, damage update, and nested reaction finishes. Choosing a reaction does not resume AI while its effects are still resolving. Stop cancels queued AI waits. A reaction pause or error stops all runners before releasing the wait; resume manually after checking any unresolved effects and counts.

Version 0.3.2 recognizes ability identities through PF2e item roll options and the standard Shield Block compendium source, in addition to explicit slugs. This supports imported or renamed Shield Block items with nullable slugs. Reaction controls now show the current Shield Block prerequisites and the last incoming damage check, including whether the ordinary reaction was already spent on Reactive Strike. This does not grant an additional reaction.

Version 0.3.3 prevents duplicate Trip outcomes with the installed PF2e Automations 1.4.9. Its asynchronous skill-check rules can add Prone and critical-success damage after the Trip call returns. AI-managed Trip rolls now carry that module's supported `skip-handling-message` option, leaving this adapter responsible for their outcomes. The critical Trip damage message carries the same marker. Regular character-sheet actions and other automation settings are unchanged. Critical failure checks the token's current synthetic actor before adding Prone. Existing duplicate conditions are not automatically deleted by this update.

Version 0.4.0 defaults to alliance targeting: Opposition creatures consider all Party combatants, and Party creatures consider all Opposition combatants, in the viewed combat scene. This includes allied NPCs on the Party side. Neutral creatures keep manual target selection and are not automatically included as enemies. Existing enabled wolves switch to the new default without resaving; old saved lists no longer restrict alliance mode. Choose **Saved manual enemies** in the controls for an explicit restriction. Automatic targeting refreshes after every action, including combatant and alliance changes. Existing visibility, condition, reach and HP checks still apply. Target scoring is unchanged; this expands the candidate pool without distributing attacks evenly.

Version 0.4.1 treats a wolf's death or incapacitation as a normal completed turn. A lethal Reactive Strike stops its movement at the reached square, confirms the reaction, and finishes the wolf's ledger without cancelling other AI runners. Dead, 0 HP, dying, unconscious, or defeated wolves also finish before choosing a new action. With **Advance to next combatant when finished** enabled, the completed turn advances once despite unused actions, including in One action mode. With it disabled, the tracker stays on the completed turn. Stop and unresolved outcomes still hold advancement. Other modules advancing the turn on death do not cause a second advance. Defeated allies are excluded from Pack Attack support when subsequent state is rebuilt.

Version 0.5.0 replaces the invented wolf weights with recovered DD behavior. It can reposition for a stronger supported attack, rather than always biting as soon as any enemy is in reach. Priority layers account for the actions/attacks remaining. Equal attacks favor staying put, then remaining exact ties are random. Preview shows the layer, utility, benchmark AC, and tie explanation. Earlier Standard/Mindless/Pack profile examples remain demonstrations and are not live NPC adapters.

Version 0.5.1 fixes friendly creatures blocking routes. The path search can cross a willing ally's space at its normal movement cost, including consecutive allied squares and the full footprint of a larger ally. Allied creatures are identified by PF2e's alliance relationship, and are assumed willing to let the NPC pass. Neutral creatures, hostile creatures and noncreature objects retain the existing blocking behavior. Walls and terrain remain subject to native constraints and measurement. The AI chooses a clear endpoint for each Stride; it does not plan the optional sequence of ending one move atop an ally and immediately spending another move to leave. See [Moving Through a Creature's Space, Player Core p. 422](https://2e.aonprd.com/Rules.aspx?ID=2360).

Version 0.5.2 fixes a false death message after healing. Foundry merges nested flag objects, so omitting `completionReason` and `incapacitationReason` did not erase a previous death from the stored ledger. New turns now explicitly reset those reasons and old advancement markers. A recovered NPC clears old incapacity reasons before resuming; new actions and Correct counts clear them as well. Reporting checks the current creature, and completion rechecks it before death-based advancement. Healing never refunds a spent action, resets MAP, or rewinds an already advanced turn. A living wolf with zero remaining actions still finishes normally. Actual Dead, Dying, Unconscious, 0 HP and defeated states remain respected; the fix does not remove conditions or edit world actor data. The regression reproduces a healed wolf taking 11 damage, remaining at 13 HP, and completing a 10-foot Stride without a false death message.

Version 0.6.0 adds the first group of [wolf maneuvers](wolf-maneuvers.md). Step avoids ordinary movement reaction prompts; Crawl stays Prone; a prone or Grabbed wolf can bite when legal; Restrained wolves can Escape. The GM supplies any missing Escape source/DC before an action is spent. Escape counts toward MAP, removes only the selected supported source, blocks retries after critical failure, and supports the optional free five-foot Stride on critical success. Remaster Knockdown uses an outcome estimate instead of legacy automatic priority. Physical attack paths are checked separately from sight. The shared DD comparator remains unchanged.

## Install and use

The build output is `dist/foundry-creature-ai`. To install its files:

```powershell
node tools/build-module.mjs
powershell -ExecutionPolicy Bypass -File tools/install-module.ps1
```

The installer copies only this module's files into `C:\Users\Roman\AppData\Local\FoundryVTT\Data\modules\foundry-creature-ai`. It does not edit world databases, create creatures, or enable the module in any world.

1. Restart Foundry if it was already running, then enable **Foundry Creature AI — Wolf** in **Manage Modules** for your PF2e world.
2. Drag a **Wolf** from the Monster Core compendium onto a scene with a 5-foot square grid. Keep its token unlinked and sized 1×1. Place enemies and any allied wolves; add the wolves and enemies to combat.
3. Set the creature's PF2e alliance to **Party** for the player side and allied NPCs, **Opposition** for their enemies, or neutral for a creature whose enemies you will select manually. The PF2e alliance is separate from token disposition color. Select one wolf token; automatic alliance mode does not require the target tool.
4. Press **Alt+W**, or click the **paw icon** in the token toolbar. **All opposing combatants (default)** considers every combatant on the other alliance in this scene. Neutral creatures use **Saved manual enemies**; use Foundry's target tool to select those enemies before saving. **Save wolf**, **Run turn**, and **One action** save the settings. Select **Act automatically at turn start** for automatic turns and **Advance to next combatant when finished** to pass the turn automatically. Enable **Prompt for Shield Block and Reactive Strike** to offer eligible reactions. **Apply damage automatically** controls HP application and enables Shield Block prompts before applying that damage.
5. On the wolf's active turn, use **Preview**, **One action**, or **Run turn**. A separate Save step is unnecessary for manual runs. Automatic mode begins on subsequent PF2e turn-start events after the system processes effects. Saving during an existing turn does not immediately run it.
6. Use **Alt+Shift+W** to request cancellation of all Wolf AI runners and pause subsequent automatic starts. A roll already resolving finishes; further actions stop. A manual run or saving a wolf with automatic starts enabled resumes them. Scene teardown also pauses automatic starts. With automatic advancement unchecked, advance the combat turn yourself.

Each wolf has its own configuration. Repeat steps 3–4 for pack members. In automatic mode, the target tool and saved manual list do not restrict opponents, and no selected targets are required. In manual mode, saving a new target set replaces the manual list; with no selected enemies, the previous list is retained. A neutral creature can explicitly target a saved creature, and an aligned creature can explicitly target a neutral creature in manual mode. Same-alliance creatures are excluded.

If keyboard shortcuts conflict, use this script macro:

```javascript
await game.modules.get('foundry-creature-ai').api.open();
```

Other API entry points are `preview()`, `runTurn()`, `runTurn(undefined, {oneAction: true})`, `stop()`, and `correctLedger()`. The functions that act on a wolf use the single controlled wolf by default. Run them from Foundry's active GM client.

Select any combatant and use the **shield icon** in the token toolbar to inspect or correct its ordinary reaction count, including reactions spent manually. The API equivalent is `game.modules.get('foundry-creature-ai').api.reactions.openControls()`.

## Wolf decisions

The wolf evaluates jaws Strikes, legal movement, Stand, Escape and eligible Knockdown. It normally stands when safe, but can bite or Crawl while Prone when appropriate. One Stand clears duplicate removable Prone entries together and verifies that Prone is gone. Locked/temporary Prone sources exclude Stand while other legal actions remain available. Movement is valued by its best supported attack after paying for the move, current MAP, flanking and known reaction exposure. The optional critical-success Escape Stride is free. With three actions a better attack position can outrank an immediate bite; with two actions and no attacks made, immediate attacks have a higher layer. Exact ties are random. Reaction prompts pause execution until fully resolved.

Pack Attack requires **two other allies** within reach of the defender. One allied wolf can help flank, but does not enable the extra Pack Attack die. The module uses the actor's existing Pack Attack rule and restores its previous toggle after each Strike.

After a successful jaws Strike with Knockdown, the next action can be Knockdown against that same target. It spends one action. For remaster wolves, the module rolls Trip without applying or increasing MAP, applies prone on success, rolls the critical-success damage, and makes the wolf prone on critical failure. For a legacy Knockdown item explicitly marked `remaster: false`, it applies prone without a Trip roll. Already-prone and immune targets are excluded.

AI Trip outcomes have one owner: this module. The installed PF2e Automations handler honors `skip-handling-message` on these particular rolls, preventing a race that otherwise creates a second Prone or another critical-success damage roll. A check immediately after an awaited Trip is insufficient because third-party chat hooks can launch asynchronous work without awaiting it. Other modules that apply Trip effects independently may require their own compatibility handler.

Actual attack rolls, damage rolls, and damage application use PF2e APIs. Decision scores use DD's recovered benchmark AC table and simplified hit chance, rather than target base AC. Foundry has no DD encounter CharacterLevel: the adapter uses the rounded mean level of character combatants, falling back to the wolf's level if none are available. Current target Prone, Off-Guard, and flanking adjust the estimate. Other situational defense modifiers are not yet reflected in decision scores. The native roll remains authoritative, including critical results, resistances and other supported system effects.

The installed DD wolf has Pack Attack but does not explicitly grant Knockdown. The Foundry item's publication marker determines legacy automatic Prone versus remaster Trip. Legacy Knockdown keeps its high priority; remaster Knockdown now compares estimated success, Prone benefit, critical damage and self-fall risk. Door opening, general Athletics maneuvers beyond supported Escape/Knockdown, spells and the remaining DD action library still need handlers. See [wolf maneuvers](wolf-maneuvers.md) for the distinction between recovered ranking and new valuations.

## Action accounting

The module stores actions remaining, attack actions made (Strikes and Escape), the immediately preceding action, visited destinations, Escape critical-failure lockout and optional free Escape movement. It reserves costs before execution. Knockdown does not increase MAP; Escape does. Running the same turn again continues the stored budget. Correct counts forfeits pending optional Escape movement and preserves the critical-failure Escape lockout for the turn.

An incapacitated wolf's ledger is marked complete with its remaining actions recorded as unused. The runner never spends those actions or tries another movement, Strike, or Stand. This completion can pass the turn when automatic advancement is enabled; it also applies when a wolf was already incapacitated at turn start. The next NPC builds a fresh snapshot, excluding dead or defeated allies from pack support and ineligible enemies from targeting. A death is not a global automation pause. Explicit Stop, manual-damage decisions, and uncertain execution errors retain their existing pause behavior.

An execution error with an unknown outcome retains its cost and marks the ledger uncertain. Use **Correct counts** after checking chat and the token's position. This explicitly sets remaining actions and Strikes already made, and clears any Knockdown follow-up. The module never automatically refunds an action whose outcome is uncertain. If Foundry explicitly reports that a Stride was stopped, the action remains spent, the reached position is recorded, and automation pauses with an explanation; the remaining budget can be retried without clearing an uncertain marker.

Before mixing manual actions with automation, update the counts. The module cannot recognize every action performed through other modules or a character sheet. It ignores Quickened's extra restricted action; Slowed reduces the ordinary three-action budget. Stunned and several other conditions stop automation for manual handling.

Rolls-only mode stops after a damaging hit. Apply the damage before resuming so the chooser can read the updated target HP. Applying damage automatically uses `ActorPF2e.applyDamage` with the damage roll object, preserving standard resistance, weakness, and immunity processing. Special ephemeral target effects, unusual damage redirection, and third-party damage workflows have not been validated.

## Boundaries of this first adapter

- Movement supports Stride, Step and Crawl for an unlinked 1×1 wolf on a 5-foot square grid, including a fractional or off-grid starting position. It measures from the actual position and preserves movement history. Willing allies can be crossed; planned endpoints are clear. Doors, climbing, jumping, flying, squeezing and transitions between elevations/scene levels remain unsupported.
- Empty Regions and Regions with only disabled behaviors do not block movement. Regions with active behaviors still require manual movement, since those behaviors can represent hazards, teleports, or other effects this adapter does not model. The GM report names the blocking Regions; the wolf can still attack from its current location.
- In alliance mode, enemies must be combatants on the opposing PF2e alliance in the viewed scene; neutral and same-alliance creatures are excluded. Manual mode requires a saved roster and active combat. Since **0.11.0**, each NPC remembers known enemy squares after losing sight and can move around obstacles to regain a view. Explicit Hidden targets retain known-square search goals; undetected/unnoticed/invisible newcomers with no prior information are not located automatically. Attack candidates require an observed target with a clear physical path, while explicit stealth and concealment checks remain manual. See [known-square memory](target-memory.md) for initialization and limits. Unconscious/dying enemies are not attack targets, and navigation between elevations or scene levels remains manual. Darkness and special senses are not simulated.
- The reaction checkbox now enables standard Shield Block and Reactive Strike prompts instead of blocking movement merely for being in reach. Reactive Strike checks all eligible enemy combatants in the viewed scene, including enemies outside the wolf's saved target roster. It uses equipped melee weapon reach and sight-line checks, and asks once per reacting creature per move action. Manual attacks/dragging, other reaction types, extra or restricted reactions, special senses, and enhanced disruption effects require separate handling; see the reaction guide.
- Only the standard wolf's jaws/Knockdown and 1d4 Pack Attack are supported. Other enemies, enhanced Knockdown variants, and arbitrary abilities need separate handlers. Automatic turn advancement requires its per-wolf checkbox and a completed turn. Incapacitation can end a turn with unused actions, including during a One action run.
- AI-managed roll messages set Workbench 7.7.5's `noAutoDamageRoll` flag to avoid duplicate auto-rolled damage. This does not change Workbench settings. Other automation-module combinations still need a live compatibility check.

## Verification

Run `node --test`. Tests cover the shared chooser; wolf targeting; exact Pack Attack ally threshold; degree-of-success arithmetic; MAP; follow-up eligibility; movement costs, obstruction and detours; turn ledgers; animation sequencing; cancellation and interrupted actions; legacy and remaster Knockdown; HP application; Workbench message marking; reaction eligibility and budgets; owner routing and cancellation; Shield Block before damage; and segmented movement reactions. On this Windows installation, additional tests import the installed Foundry 14 square-grid implementation to check accumulated movement costs, diagonal parity, and route smoothing. Those optional tests skip when that installation is unavailable. The owner query tests use simulated clients; a real multiplayer smoke test remains necessary.

For the first live check, use a disposable encounter with a standard wolf and one enemy, then add a second and third wolf. Check that one ally gives no extra Pack Attack die and two allies give one d4. Confirm damage is rolled/applied once, Knockdown is offered only after a successful jaws Strike, and a repeated **Run turn** does not grant additional actions. Test the advance checkbox both ways and confirm **One action** and manual-damage pauses retain the current combatant.

For target selection, add two Party combatants and a neutral creature. An Opposition wolf in default mode should consider both Party creatures without manual targeting, and leave the neutral out. Change the wolf to Party and confirm only Opposition combatants become candidates. A neutral wolf requires a manual list. Check that a new opponent entering combat becomes eligible and that changing an enemy to the same alliance removes it before the next action.

For death handling, use a wolf with low HP and a character with Reactive Strike. Verify a lethal reaction stops further movement and attacks, finishes the wolf's turn, and advances only with automatic passing enabled. Then place another automated wolf next in initiative and verify its turn runs normally. Check that death after Stand behaves the same way and that pressing Stop still prevents advancement.

The implementation's rule sources are the [PF2e Monster Core Wolf definition](https://github.com/foundryvtt/pf2e/blob/v14-dev/packs/pf2e/pathfinder-monster-core/wolf.json), the installed PF2e 8.6.1 bundle, and the [Foundry 14 Token movement API](https://foundryvtt.com/api/v14/classes/foundry.documents.TokenDocument.html#move). The project contains no game DLLs or copied Dawnsbury implementation.
