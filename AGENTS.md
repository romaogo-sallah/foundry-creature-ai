# Project workflow

The user wants completed work committed and pushed to GitHub by default.

- After finishing changes and appropriate verification, commit the task's files and push the current branch to `origin` (`https://github.com/romaogo-sallah/foundry-creature-ai.git`).
- Push release tags created for that completed work as well. Keep release archives and verification records with their release commits.
- Preserve unrelated user changes. Do not force-push or rewrite published history.
- If authentication, permissions, remote changes or checks block a push, report the actual blocker and keep the completed local commit available.
- Never commit credentials, Foundry world databases, `.scratch/`, or generated `dist/` files.

# Table adjudication defaults

- The user authorizes the agent to resolve routine GM-discretion cases autonomously. Prefer a consistent, scriptable policy and document it; do not pause implementation merely because the rules delegate judgment to the GM.
- For competing behavioral compulsions, use **Fleeing > Confused > Controlled**. Lower conditions retain their other effects, including Confused's reaction denial. Resume the next active directive when the higher one ends.
- A newly applied Fascinated source replaces older fascination rather than retaining multiple subjects or reverting to an older source later. Preserve unrelated effects belonging to older granting items.
- Distinguish chosen table policies from universal PF2e rules. Source metadata, unknown creature knowledge and existing automation ownership still constrain what can be resolved automatically.
